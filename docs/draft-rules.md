# 記事下書き（drafts）執筆ルール

`drafts/` 配下で記事や実績紹介の下書き（Markdown）を作成・編集する際のガイドラインです。

---

## 1. 装飾・記法の禁止事項

### 太字（Bold）の禁止
記事本文・リスト・テーブル内を問わず、**太字記法（`**...**`、`__...__`、`<strong>`、`<b>`）は使用しないでください**。

### 水平線（`---` / `<hr>`）の禁止
セクションの区切りに水平線（`---`）を挿入しないでください（先頭の frontmatter 囲みを除く）。
セクション間の区切りは、見出し（`h2`, `h3`）自体の余白とスタイルによって自然に表現されます。

### コードブロック内での非コード記述の禁止
コードブロック（```` ``` ````）は実際のプログラムコードやシェルコマンド専用です。
フロー図、アスキーアート、矢印付きテキストなどの非コードをコードブロック内に記述しないでください。
処理手順や画面遷移フローを表現する場合は、順序付きリスト（`1.`, `2.`, `3.`）や箇条書きリスト、または通常の文章によって表現します。

### 禁止の背景・理由
- **視覚的ノイズの低減**: ページ内に過度な線や太字が点在すると視線が散り、長文の可読性や落ち着いたトーンが損なわれます。
- **構造化による表現の促進**: 装飾記号に頼るのではなく、見出しやリスト、適切な段落分けといった文章構造によって自然に要点を伝える執筆を徹底します。

---

## 2. 強調・要点提示の代替手段

要点を際立たせたい場合は、太字や水平線ではなく以下の構造化・記法を活用します。

1. **見出し（`h2`, `h3`）によるセクション分け**
   - 論点ごとに見出しを設け、内容を明確に区切ります。セクション間の水平線は引かず、見出しのみで遷移させます。
2. **箇条書きリスト（`-` / `1.`）**
   - 特徴や手順、要点を整理して列挙します。
3. **カギ括弧（「」）の活用**
   - 特定のキーワードや概念、名称を目立たせたい場合はカギ括弧で括ります。
4. **インラインコード（`` `code` ``）**
   - 技術名、API名、コマンド、ファイルパスなどの専門用語はインラインコードを使用します。
5. **簡潔で明瞭な文構造**
   - 1文を短く保ち、要点がダイレクトに伝わる推敲を行います。

---

## 3. 技術スタックの記載ルール

実績紹介における「技術スタック」セクションは、以下の 5 つの区分を用いて**採用技術のみをシンプルに列挙**します。

### 5 つの区分
1. **言語**
2. **フレームワーク**
3. **OS**
4. **インフラ**
5. **その他**

### 記述形式のルール
- カテゴリ名や選定理由の解説文は記載せず、採用技術名のみをカンマ区切り等で列挙します。
- Tailwind CSS や shadcn/ui などの CSS / UI ライブラリも「フレームワーク」区分に含めます。
- 該当する技術がない区分は省略します。
- 箇条書きリスト形式で記述します。

```markdown
## 技術スタック

- 言語: TypeScript, Python
- フレームワーク: Next.js (App Router), Tailwind CSS, shadcn/ui
- OS: macOS
- インフラ: Vercel
```

## 4. 基本テンプレート（Frontmatter）

下書きは以下の frontmatter を持つ Markdown 形式で管理します。

```markdown
---
title: "タイトル"
description: "概要説明文"
date: "YYYY-MM-DD"
tags: ["タグ1", "タグ2"]
demoLink: "https://example.com" # 任意
codeLink: "https://github.com/..." # 任意
---

## 概要

本文...

## 開発の背景と目的

本文...

## 主な機能

- 機能1: 説明...
- 機能2: 説明...

## 技術スタック

- 言語: TypeScript
- フレームワーク: Next.js, Tailwind CSS
- OS: macOS
- インフラ: Vercel

## 工夫した点

- 工夫点1: 説明...
- 工夫点2: 説明...
```
