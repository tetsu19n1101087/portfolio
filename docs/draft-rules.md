# 記事下書き（drafts）執筆ルール

`drafts/` 配下で記事や実績紹介の下書き（Markdown）を作成・編集する際のガイドラインです。

---

## 1. 太字（Bold）の禁止

記事本文・リスト・テーブル内を問わず、**太字記法（`**...**`、`__...__`、`<strong>`、`<b>`）は使用しないでください**。

### 禁止の背景・理由
- **視覚的ノイズの低減**: ページ内に太字が頻出すると視線が散り、長文の可読性や落ち着いたトーンが損なわれます。
- **構造化による表現の促進**: 単語を強調装飾するのではなく、見出しやリスト、適切な段落分けといった文章構造によって自然に要点を伝える執筆を徹底します。

---

## 2. 強調・要点提示の代替手段

要点を際立たせたい場合は、太字ではなく以下の構造化・記法を活用します。

1. **見出し（`h2`, `h3`）によるセクション分け**
   - 論点ごとに見出しを設け、内容を明確に区切ります。
2. **箇条書きリスト（`-` / `1.`）**
   - 特徴や手順、要点を整理して列挙します。
3. **カギ括弧（「」）の活用**
   - 特定のキーワードや概念、名称を目立たせたい場合はカギ括弧で括ります。
4. **インラインコード（`` `code` ``）**
   - 技術名、API名、コマンド、ファイルパスなどの専門用語はインラインコードを使用します。
5. **簡潔で明瞭な文構造**
   - 1文を短く保ち、要点がダイレクトに伝わる推敲を行います。

---

## 3. 基本テンプレート（Frontmatter）

下書きは以下の frontmatter を持つ Markdown 形式で管理します。

```markdown
---
title: "タイトル"
description: "概要説明文"
date: "YYYY-MM-DD"
tags: ["タグ1", "タグ2"]
demoLink: "https://example.com" # 任意
codeLink: "https://github.com/..." # 任意
---

## 概要

本文...
```
